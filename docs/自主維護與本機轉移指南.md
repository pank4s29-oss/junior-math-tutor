# 國中數學解題教練：自主維護與本機轉移指南

> **目的**：本指南讓專案所有人能在自己的電腦維護程式、將版本推送至 GitHub、套用 Supabase 資料庫變更，並由 Vercel 自動部署。完成交接後，日常修改不需要透過 Manus。

## 1. 架構與責任範圍

| 資產 | 所在位置 | 日後自行維護方式 |
|---|---|---|
| React、Express、tRPC、Gemini 程式碼 | GitHub repository | 在本機修改、測試、commit、push |
| SQL schema、資料庫函式、trigger | GitHub `supabase/migrations/` | 新增 migration，測試後以 Supabase CLI 套用 |
| 使用者資料、登入帳號、私有題目照片 | Supabase | 透過 Supabase Dashboard、RLS、Storage 與備份管理 |
| 正式網站與環境變數 | Vercel | 將 repository 連結至專案；由 Git push 觸發部署 |
| Gemini API key | 本機 `.env.local`／Vercel Environment Variables | 僅供 server-side 使用，絕不放進 `VITE_` 變數或 Git |

**GitHub 是程式與 migration 的版本來源；Supabase 是資料與檔案的運行來源。** Git clone 不會自動下載真實學生資料、Auth 使用者或 Storage 題目照片。若您需要離線備份，請依第 7 節個別匯出，且不要將含學生資料的檔案提交至 Git。

## 2. 第一次下載到自己的電腦

先安裝目前 LTS 版 Node.js、Git，以及 pnpm（`corepack enable` 即可使用 package.json 所指定版本）。接著在終端機執行：

```bash
git clone https://github.com/<您的帳號>/junior-math-tutor.git
cd junior-math-tutor
corepack enable
pnpm install --frozen-lockfile
cp config/env.local.template .env.local
```

請在 `.env.local` 填入自己的值，但絕對不要把檔案加入 Git。此專案已忽略 `.env*`，而範本本身只保留變數名稱，沒有任何機密。

| 變數 | 是否可出現在瀏覽器 | 取得位置／用途 |
|---|---:|---|
| `VITE_SUPABASE_URL` | 可以 | Supabase Project URL；此值公開不會授權資料庫管理 |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | 可以 | Supabase Publishable／anon key；供 Magic Link 客戶端使用 |
| `SUPABASE_URL` | 不要 | 同一個 Project URL，供 server-side client 使用 |
| `SUPABASE_SECRET_KEY` | **不可以** | Supabase server-side secret key；存取私有 Storage 與受保護資料 |
| `SUPABASE_DB_URL` | **不可以** | 僅作 migration／維運腳本的 PostgreSQL 連線 |
| `GEMINI_API_KEY` | **不可以** | Google AI Studio；僅允許 Vercel Function 呼叫 Gemini |
| `TUTOR_API_PORT` | 可以 | 本機 API port，預設 `3001` |

## 3. 本機啟動、測試與正式建置

專案新增了不依賴受管登入服務的本機開發入口。執行下列命令會同時啟動 Vite 前端與獨立 Express/tRPC API；瀏覽器的 `/api` 請求會代理到本機 API，不需要本機模擬 Vercel。

```bash
pnpm dev
```

開啟終端機顯示的 Vite 網址（通常是 `http://localhost:5173`）。在送出任何 commit 前，固定執行：

```bash
pnpm test
pnpm check
pnpm build:client
pnpm verify:local
```

這三項分別驗證行為契約、TypeScript 與 Vite production 輸出。Gemini 實際連線測試會使用 `.env.local` 的 server-side key；若金鑰不可用，先在 Google AI Studio 確認 API key、帳戶權限與模型可用性，切勿為了通過測試把 key 寫入原始碼。

`pnpm verify:local` 會暫時啟動一組獨立連接埠的 Express API 與 Vite，並自動確認 Vite `/api` proxy 可取得 `{ ok: true }` 後關閉程序。如果 `pnpm dev` 出現 `EADDRINUSE`，代表 `3001` 或 `5173` 已有舊程序在執行；關閉該終端機中的舊 `pnpm dev`，或將 `.env.local` 的 `TUTOR_API_PORT` 改為未使用的連接埠，再以相同值重新啟動。若改動連接埠，請一併在 `vite.config.ts` 的 proxy 目標使用該環境變數設定。

## 4. 日後修改資料庫：以 migration 為唯一流程

現有 migrations 位於 `supabase/migrations/`。**已在目前 Supabase project 套用的 01–05 migration 不要以手動 SQL Editor 重複執行。** 對既有正式專案，先安裝 Supabase CLI、登入並連結；再以乾跑確認差異：

```bash
npx supabase login
npx supabase link --project-ref <您的 Supabase project ref>
npx supabase migration list
npx supabase db push --dry-run
```

當您要新增資料表、欄位、RLS policy 或 RPC 時，先建立新的 migration，再在本機／預覽環境驗證：

```bash
npx supabase migration new add_learning_feature
# 編輯新產生的 supabase/migrations/<timestamp>_add_learning_feature.sql
npx supabase db push --dry-run
npx supabase db push
git add supabase/migrations
git commit -m "db: add learning feature"
git push origin main
```

Supabase 會以 migration history 追蹤已經套用的版本；如果既有遠端 schema 曾被直接手動更改，先使用 `npx supabase migration list` 判斷差異，再使用 `npx supabase db pull` 建立新的對應 migration。不要用 `db reset --linked` 對正式資料庫執行，因為它會清除遠端自訂資料。[1] [2]

## 5. GitHub 與 Vercel 發布流程

建議使用 feature branch 先取得 Vercel Preview；確認登入、解題、照片、錯題與教師功能後才合併至 `main`。

```bash
git checkout -b feature/my-change
# 修改、pnpm test、pnpm check、pnpm build:client
git add client server supabase docs package.json pnpm-lock.yaml
git commit -m "feat: describe your change"
git push -u origin feature/my-change
```

在 Vercel 中，Preview 與 Production 必須各自設定與本機相同的環境變數名稱；**值不同是正常的，但名稱不可不同**。若 `main` 是 Production Branch，合併或推送到 `main` 後 Vercel 會自動建立 production deployment；其他分支會建立 preview deployment。[3]

目前 deployment 相關設定受 repository 中的 `vercel.json`、`server.ts` 與 `vite.config.ts` 管理。不要把 Vercel 的 Build Output Directory 改為自訂 command；此專案由 `pnpm build:client` 產生 `public/`，並由 Vercel 執行 Express/tRPC serverless 入口與 SPA fallback。

## 6. 上線後的必要例行檢查

每次改動登入或網域時，請在 Supabase **Authentication → URL Configuration** 更新 Site URL 與 Redirect URLs，至少保留正式 Vercel 網域與必要的 localhost 開發網址。Magic Link 使用者在 `auth.users` 建立時，資料庫 trigger 會安全建立最低權限 `student` 的 `profiles` 與 `app_users` 紀錄；教師／管理員的角色只能從 Supabase 受保護資料庫角色欄位提升，不能用前端 metadata 操作。

上線前請以兩個測試帳號驗證：第一個學生帳號可登入、上傳自己的題目、解題與查看自己的歷程；第二個帳號不得讀取第一個帳號的資料。再以教師帳號確認 `/teacher` 僅在 `profiles.role` 為 `teacher` 或 `admin` 時可使用。這是比單純看到 HTTP 200 更重要的資料隔離驗證。

## 7. 自己電腦的備份策略

| 要備份的內容 | 建議方式 | 不應做的事 |
|---|---|---|
| 程式碼與 SQL migrations | GitHub private repository + 本機 `git clone` | 將 `.env.local`、token、或 Vercel env 匯出檔 commit |
| Supabase schema | `npx supabase db dump -f backups/schema.sql`；加密保存 | 直接修改正式 schema 後不建立 migration |
| 學習資料 | 依保留政策使用 `npx supabase db dump --data-only` 或 Supabase 的備份／匯出機制 | 把含學生資料的 SQL dump 上傳公開 GitHub |
| 私有題目照片 | Supabase Storage Dashboard／受權腳本匯出，加密離線保存 | 將題目照片放進 public bucket 或 repository |
| Vercel／Gemini／Supabase 金鑰 | 密碼管理器，並定期輪替 | 存在筆記、截圖、Git、前端或聊天訊息 |

`db dump` 只會匯出可用的資料庫內容；Auth 與 Storage 有各自的管理邊界，學生資料與私有檔案應依個資與保留政策另外備份。[2]

## 8. 可移除的受管遺留程式

本專案的正式可攜路徑是 `server.ts` → `server/app.ts` → Supabase／Gemini，及前端的 Supabase Magic Link。`server/_core/` 中仍保留部分原 scaffold 的受管 OAuth、Storage 與通知檔案，方便回溯早期版本，但 Vercel entry 不會掛載它們。待您以真實帳號完成所有 Vercel 流程驗證、且建立自己的備份後，可在另一個 branch 移除未被 `server/app.ts` 或 `server/routers.ts` 匯入的遺留檔案；每次移除後都要執行第 3 節的三項檢查。
