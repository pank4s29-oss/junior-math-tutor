# 多題解題工作階段使用說明

## 學生端

學生登入後可一次選取多個照片、PDF、TXT 或 Markdown 題目檔。系統會在第一題送出時建立一個多題解題工作階段，之後逐題沿用同一個工作階段，不需要重新上傳下一題。每一題完成後，下一份檔案會自動成為目前題目；最後一份題目仍會保留在輸入區，因此學生可以直接輸入追問，系統會沿用同一份附件與對話，不必重拍或重新匯入。

辨識與解題是兩個不同步驟。辨識只用來讀取圖片／PDF 的文字並讓學生核對，不會消耗解題額度或啟動解題冷卻；真正送出解題時才計算一次額度。若 Gemini 暫時繁忙，題目佇列與目前附件會保留，學生稍候即可重試。

## 教師端

教師／管理者可在工作台的「解題工作階段」區塊選擇每批 **5 題或 10 題**，並按「儲存上限」。限制只套用於新建立的工作階段；已經開始的批次不會中途改變。伺服器仍會再次驗證題數與 session 擁有者，學生無法透過前端繞過上限或讀取其他學生的工作階段。

## 維護與限制

批次工作階段只保存學生本人、年級、單元、題數與狀態等最小 metadata；題目檔案仍走既有的私有 Supabase Storage，對話與解題紀錄仍依本人 UUID 隔離。清除最後一份目前題目後，前端會結束本地批次識別，下一次匯入會建立新的工作階段。

目前工作階段採逐題處理，目的是讓每題都能獲得完整固定格式的教學回覆，並允許每題獨立追問；它不是把十題合併為一個超長模型請求。未來若需要「一次回傳整份十題答案」，應另行設計輸出格式與額度策略，不應直接放寬現有單題回覆上限。
